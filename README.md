# Twitch VOD Unmute — Modded

Расширение для Chrome, которое возвращает звук в заглушённых участках записей стримов Twitch (VOD).

Это модифицированный форк [Twitch VOD Unmute](https://chromewebstore.google.com/detail/twitch-vod-unmute/kjbnfiobdlebmfgeklpfjjhcjfpbnkhf) с переписанным ядром: добавлены поддержка fMP4-плейлистов, работа с несколькими качествами, откат на более низкое качество, живая статистика в popup и подсветка восстановленных участков прямо на полосе прокрутки плеера.

## Зачем это нужно

Когда Twitch находит в записи защищённую авторским правом музыку, он не удаляет звук, а подменяет аудиодорожку: плеер начинает запрашивать файлы вида `...-muted.ts`. При этом оригинальные файлы без `-muted` часто ещё лежат на CDN. Расширение находит такие сегменты и незаметно подменяет запросы плеера на оригиналы — звук возвращается без перезаливки видео.

## Как это работает

```text
плеер грузит index-muted-*.m3u8
        │
        ▼
плейлист скачивается из контекста страницы Twitch  (иначе CDN отдаёт 403)
        │
        ▼
заглушённые сегменты проверяются пакетами по 6 запросов (Range: bytes=0-1)
        │
        ▼
на каждый доступный оригинал ставится своё правило redirect (declarativeNetRequest)
        │
        ▼
восстановленные участки закрашиваются на seekbar плеера
```

Несколько важных деталей реализации:

- **Всё сетевое общение идёт через страницу.** Запросы из origin расширения CDN Twitch отбивает `403`, поэтому и загрузка плейлиста, и проверка сегментов выполняются через `chrome.scripting.executeScript` внутри вкладки.
- **Сегменты не скачиваются целиком.** Проверка — это запрос двух байт (`Range: bytes=0-1`), который обрывается сразу после получения кода ответа.
- **Повторы только там, где они имеют смысл.** `404`/`410` — это окончательный ответ и проверяется один раз; `429` и `5xx` считаются временными и повторяются до трёх раз с нарастающей паузой.
- **Результаты кешируются.** Плеер перезапрашивает плейлист много раз, поэтому окончательные коды ответов хранятся 10 минут и повторно сегменты не дёргаются.
- **Правила точные, по одному на сегмент.** Широкое regex-правило перенаправляло бы и те сегменты, у которых оригинала нет, и плеер получал бы `404`. Недоступные сегменты просто остаются приглушёнными.
- **Лимит правил Chrome учитывается.** Сессионных правил конечное число, и они делятся на все вкладки и расширения. Если места хватает не на всё, часть сегментов пропускается и об этом честно пишется в popup.
- **Проверяется только то качество, которое реально смотрит пользователь.** Расширение следит за тем, какие сегменты запрашивает плеер, и при смене качества на ходу перепроверяет уже известный плейлист нового рендишна.
- **Адреса сегментов разбираются по правилам HLS.** Строки плейлиста могут быть относительными (`1.ts`, `../480p30/1.ts`) или абсолютными, поэтому каждый URI разрешается относительно адреса плейлиста.
- **fMP4 обрабатывается аккуратно.** Если в плейлисте есть init-сегмент (`#EXT-X-MAP`), он тоже подменяется — иначе декодер настраивается по приглушённой дорожке и Twitch выдаёт ошибку #2000. Для fMP4 откат на более низкое качество отключается, чтобы не смешивать несовместимые дорожки.
- **Подсветка выживает перерисовку плеера.** Фуллскрин, театральный режим и переходы внутри Twitch пересобирают seekbar, поэтому `MutationObserver` возвращает заливку на место.
- **Состояние живёт только в сессии.** Правила привязаны к вкладке (`condition.tabIds`) и снимаются при навигации, закрытии вкладки и выключении расширения.

## Возможности

| Возможность | Что делает |
|---|---|
| Восстановление звука | Подменяет `-muted` сегменты на доступные оригиналы. |
| Откат по качеству | Если оригинала в текущем качестве нет, ищет его в более низких (кроме fMP4). |
| Подсветка seekbar | Красит восстановленные участки в полосе прокрутки с учётом длительности сегментов; отдельный цвет для восстановленных из низкого качества. |
| Статистика | Показывает, сколько сегментов восстановлено, сколько из низкого качества и сколько осталось недоступно, вместе с текущим качеством и прогрессом проверки. |
| Настройки | Цвета, прозрачность подсветки, вкл/выкл подсветки и отката по качеству, экспорт настроек в JSON. |

## Установка

1. Скачайте или клонируйте репозиторий:
   ```bash
   git clone https://github.com/engix3/twitch-vod-unmute-modded.git
   ```
2. Откройте `chrome://extensions/` и включите **режим разработчика**.
3. Нажмите **Load unpacked** и выберите папку с расширением.
4. Откройте любую запись: `https://www.twitch.tv/videos/<id>`.

Нужен Chrome 102 или новее (Manifest V3).

## Использование

Расширение работает само: откройте VOD и подождите, пока в popup появится статистика. Дальше **перемотайте на заглушённый участок** — правила действуют на новые запросы, поэтому уже загруженный сегмент останется без звука, пока плеер не запросит его снова.

В popup доступны переключатели, цвета подсветки, кнопка перезагрузки вкладки и экспорт настроек. Переключатели применяются сразу: включение расширения или отката по качеству запускает перепроверку известных плейлистов, а смена цветов — перерисовку подсветки.

## Разрешения и зачем они

| Разрешение | Зачем |
|---|---|
| `declarativeNetRequest` | Подмена запросов заглушённых сегментов. |
| `webRequest` | Наблюдение за плейлистами и сегментами (без блокирующих обработчиков). |
| `scripting` | Загрузка плейлиста, проверка сегментов и отрисовка seekbar в контексте страницы. |
| `storage` | Хранение настроек. |
| `tabs` | Определение активной вкладки и очистка состояния. |
| host-доступ к `twitch.tv`, `ttvnw.net`, `cloudfront.net` | Домены страницы и CDN, откуда идут сегменты. |

## Ограничения

- Звук восстанавливается **только если Twitch ещё хранит файл без `-muted`**. Если оригинал удалён — сделать ничего нельзя.
- Правила существуют только в рамках сессии браузера и не переживают его перезапуск.
- У сессионных правил есть лимит (около 5000 на браузер): очень долгая запись с тысячами заглушённых сегментов может быть восстановлена не полностью.
- Подсветка опирается на разметку `div.seekbar-bar`, которую Twitch может в любой момент изменить.
- Для fMP4-записей откат на более низкое качество недоступен by design.

## Что поправлено в 1.8.0

- Адреса сегментов больше не склеиваются строками: относительные и `../`-пути разбираются корректно.
- Маркер `-muted` теперь привязан к концу имени файла, так что `1-mutedmix.ts` больше не принимается за заглушённый сегмент.
- Проверка сегментов идёт через `Range: bytes=0-1` вместо скачивания файлов, а окончательные результаты кешируются.
- Логика повторов исправлена: `404` больше не перезапрашивается три раза, а `429`/`5xx` — перезапрашиваются.
- Лимит сессионных правил больше не переполняется молча: пропущенные сегменты показываются в popup, а ошибки API обрабатываются.
- Подсветка возвращается после перерисовки плеера и обновляется при смене цветов без перезагрузки страницы.
- Обратное включение расширения сразу перепроверяет известные плейлисты вместо тишины до перезагрузки.
- При переходе на другую запись старое состояние вкладки полностью сбрасывается.
- popup переведён на русский, показывает текущее качество и опрашивает статистику реже, когда работа завершена.
- Код разбит на модули, мёртвые функции удалены, тесты покрывают все эти сценарии.

## Разработка

Тесты запускаются штатным раннером Node (без зависимостей):

```bash
node --test
```

Структура:

| Файл | Роль |
|---|---|
| `background.js` | Service worker: детект плейлистов, очередь проверок, кеш ответов, статистика и очистка состояния. |
| `helpers.js` | Парсинг M3U8, работа с URL, классификация ответов, расчёт участков seekbar. |
| `net.js` | Загрузка плейлиста и проверка сегментов в контексте страницы, включая повторы. |
| `rules.js` | Выдача id, лимиты и установка правил `declarativeNetRequest`. |
| `seekbar.js` | Отрисовка подсветки и её восстановление после перерисовки плеера. |
| `popup.html` / `popup.js` | Интерфейс: настройки и статистика. |
| `*.test.js` | Тесты на `node:test`. |

Текущая версия — `1.8.0` (см. `manifest.json`).
