# Twitch VOD Unmute Enhanced

## Версия 1.6.0

Причина, по которой предыдущие версии не восстанавливали звук, найдена: CDN Twitch отвечает `403` на запросы сегментов из origin расширения, но нормально отдаёт те же файлы при запросе из контекста страницы Twitch. Именно поэтому оригинальное расширение проверяет сегменты через `chrome.scripting.executeScript`, а не напрямую из service worker.

Схема работы:

```text
webRequest замечает index-muted-*.m3u8
        |
        v
плейлист скачивается ВНУТРИ страницы Twitch
        |
        v
кандидаты проверяются ВНУТРИ страницы (пакеты по 6)
        |
        v
точное правило redirect на каждый доступный сегмент
        |
        v
seekbar перекрашивается в самом плеере Twitch
```

### Что изменено относительно 1.5.0

- Проверка доступности и загрузка плейлиста выполняются через инъекцию в страницу, а не из worker: это устраняет поголовные `403`.
- Redirect снова точный, по одному правилу на сегмент, как в оригинальном расширении: широкое regex-правило перенаправляло бы и сегменты, у которых оригинал удалён.
- Сегменты без доступного оригинала просто не получают правило и остаются приглушёнными, поэтому плеер не получает `404`.
- Проверка идёт пакетами по 6 запросов с `Range: bytes=0-1`, ответ `206` считается успешным.
- В popup показывается убывающий счётчик проверяемых сегментов.
- Seekbar рисуется внутри `div.seekbar-bar` через клон существующего span, как в оригинале, поэтому геометрия совпадает с полосой плеера. Отдельный fixed-overlay удалён.
- Добавлен цвет для сегментов, восстановленных из более низкого качества.
- Позиции на seekbar считаются по порядковому индексу сегмента в плейлисте, а не по числам из имени файла.
- Правила ограничены вкладкой через `condition.tabIds` и удаляются при навигации, закрытии вкладки и выключении расширения.
- Повторная загрузка того же плейлиста не создаёт дубликаты правил.

## Возможности

| Возможность | Поведение |
|---|---|
| Восстановление | Redirect `-muted` сегментов на доступные оригиналы. |
| Fallback качества | Опционально проверяются более низкие качества. |
| Seekbar | Восстановленные участки окрашиваются в полосе плеера. |
| Статистика | Восстановленные, восстановленные из lower качества, недоступные. |
| Экспорт | Сохраняет настройки в JSON. |

## Установка

1. Откройте `chrome://extensions/`.
2. Включите режим разработчика.
3. Нажмите Load unpacked и выберите папку расширения.
4. Откройте страницу вида `https://www.twitch.tv/videos/<id>`.

## Разрешения

| Разрешение | Назначение |
|---|---|
| `declarativeNetRequest` | Redirect сегментов. |
| `webRequest` | Наблюдение плейлистов без блокирующего обработчика. |
| `scripting` | Проверка сегментов и отрисовка seekbar в контексте страницы. |
| `storage` | Настройки. |
| `tabs` | Активная вкладка и очистка состояния. |

## Ограничения

Восстановление возможно только пока Twitch хранит файл без `-muted`. Правило действует на новые запросы: уже загруженный сегмент останется приглушённым, пока плеер не запросит его снова, поэтому после установки правил нужно перемотать на заглушённый участок. Session rules не сохраняются после закрытия браузера. Отрисовка seekbar зависит от разметки `div.seekbar-bar`, которую Twitch может изменить.
